# MR5 1.0.3 — Раскладка flash и происхождение конфигов (ответ на вопрос об effect_cfg)

Дата: 2026-11-18. Файл: `source/decrypted/MR5_1.0.3_1c89dcaf_dec.bin`
(0xAA50C = 697 612 Б — расшифрованная app-область из .ufw; флеш 2 МБ).

## 1. Ответ: гипотеза «effect_cfg ≡ ресурсный том хвоста» — ОПРОВЕРГНУТА

TLV-том, разобранный в C1.2 (hdr@0x9B390, payload 0xF15C) — это **не**
`effect_cfg.bin`, а **флеш-файл `stream.bin`**. Доказательство: перед томом
лежит 32-байтный заголовок-инода файловой системы JieLi (jlfs):

```
0x9B390: 41 91 68 4C | 20 00 00 00 | 7C F1 00 00 | 82 FF 01 00 | "stream.bin"
         id=0x4C689141  hdr=0x20   size=0xF17C   attr        имя в самой иноде
```

Полный размер записи (0xF17C = 61 820 Б, включая заголовок) ровно
заканчивается на EOF файла (0x9B390 + 0xF17C = 0xAA50C).

Функционально содержимое то же, что считалось «effect_cfg»: граф узлов +
заводские конфиги эффектов (tag 5: 185 EQ / 2 DRC / 59 GAIN). Т.е. **заводские
эффект-конфиги живут в stream.bin**, а `flash/res/effect_cfg.bin` — отдельный
файл (вероятно, оверрайды от тулинга / cfg_tool), которого **нет в нашем
дампе**. Оба пути фигурируют в пуле строк кода:

- `flash/res/effect_cfg.bin` @VA 0x0605FAAF (рядом с тегом `bt_test.base`)
- `flash/res/stream.bin`  @VA 0x0605FEFA (рядом с тегами задач `aec`,
  `jlstream` — читается jlstream-таском)
- `flash/res/` @VA 0x06062153, `cfg_tool.bin` @VA 0x060722E2

## 2. Встроенные флеш-файлы в нашем дампе (не только app!)

Хвост образа (после XIP-кода) — область jlfs с файлами, упакованными встык,
`size` = запись целиком (заголовок 32 Б + данные):

| Файл | Смещение в dec | Размер | id | Содержимое |
|---|---|---|---|---|
| `cfg_tool.bin` | 0x9831E | 0xEA (234 Б) | 0xED909943 | конфиг продукта (см. §3) |
| `p11_code.bin` | 0x98408 | 0x2F88 (12 168 Б) | 0x3B4FF3FC | код P11-ядра (PMU/сенсор) |
| `stream.bin` | 0x9B390 | 0xF17C (61 820 Б) | 0x4C689141 | аудио-граф + зав. эффекты (разобран в C1.2/DSP_ARCH) |

Проверка цепочки: 0x9831E+0xEA = 0x98408 (p11) → +0x2F88 = 0x9B390
(stream) → +0xF17C = 0xAA50C = EOF ✓.

`flash/res/effect_cfg.bin` в дампе отсутствует (magic-инод не найден) —
нужен полный OTA/.ufw или сервисный дамп всего флеша.

## 3. cfg_tool.bin — расшифровка (полная, 234 Б)

TLV-конфиг тулинга (new_cfg_tool):

- `c6 00 00 00` — тег/длина; `4f 00 00 03` — версия/число записей 3;
- строки: `soundbox`, `JL701N`, `JL701N-demo`, `1.0.0`, `patch_01`;
- `01 00 3c 27 62 02 08 00 45 4f` — ключ/опции;
- MAC Bluetooth: `A4 DB A5 DB A6 DB` (двойные записи `a4 db / a5 db / a6 db`
  в поле `04 01`);
- `f2 0a 02 01 07 84 76 / 43 4f 01 00 08 07 85 76 / 29 0d 01 00 08 51 65` —
  параметры каналов;
- `10 02 01` + **`EDIFIER MR5`** — имя устройства;
- хвост `76 66 60 00 47 ff ff`.

## 4. Найден недопокрытый код (важно для Ghidra-проекта)

Область dec 0x8EEFC..0x9831E (VA **0x0608EFFC..0x0609841E**, ≈37.9 КБ) —
это **продолжение XIP-кода pi32v2** (не стёртые 0xFF), но `app_bin_full.bin`
(основа текущего Ghidra-проекта) обрезан на 0x8EEFC. Текущий анализ
(функции=3 509, листинг) эту зону не покрывает. Для полного покрытия нужно
пересобрать проект на полном `MR5_1.0.3_1c89dcaf_dec.bin` (или добавить
сегмент 0x0608EFFC..0x0609841E).

## 5. Что осталось вне дампа (для C2)

- `flash/res/effect_cfg.bin` — оверрайды эффектов (если предусмотрены);
- остальная часть 2 МБ флеша (VFS-разделы, калибровка, OTA-слоты) —
  только полный сервисный дамп.

Практический вывод: для C2 (конфиги эффектов) критичный контент — заводские
значения — уже есть (stream.bin встроен и разобран). Отсутствует лишь
пользовательский слой (effect_cfg.bin), который на устройстве может
создаваться при первом тюнинге.
