# B2 — Опорные точки по строкам: результаты

Дата: 2026-11-18. Инструмент: `tools/xref_strings.py`, отчёт:
`disasm/string_xrefs.md`, машинный слой: `disasm/function_strings.json`.
Хелпер для чтения функций: `tools/show_func.py sub_XXXXXXXX`.

## 1. Метод

1. Извлечены строки из `app.bin` (печатные последовательности ≥4; терминатор
   — любой непечатный байт; 5 488 строк).
2. Прямые ссылки: imm-операнды в листинге `disasm/mr5_app_disasm.txt`,
   указывающие в XIP-окно (адрес = 0x06000100 + смещение файла).
3. Raw-скан mov32 по **всему** бинарнику: кодировка `C0–CF FF <imm32 LE>`
   (6 Б) — ловит ссылки из кода, недостижимого рекурсивным дизасмом.
4. Структурные ссылки: код грузит базу структуры/таблицы, внутри которой
   строка лежит инлайн (окно 512 Б до строки).

## 2. Статистика

| метрика | значение |
|---|---|
| строк в app.bin | 5 488 |
| строк с прямыми ссылками | 89 |
| mov32-ссылок всего (raw) | 1 115 |
| … внутри декодированного кода | 867 |
| … **вне** декодированного кода | **248** |
| строк-инлайн в структурах (база рядом) | 1 486 |

## 3. Главные выводы

1. **30,7 % «недизассемблированных» байт — это не только данные.** 248
   mov32-ссылок на строки лежат вне декодированных функций ⇒ там есть
   недостижимые прямой рекурсией функции (косвенные вызовы через
   таблицы обработчиков). Их адреса — готовые кандидаты стартов функций
   для этапа A3/Ghidra: raw-скан в `string_xrefs.md` помечает их
   «(вне декода)».
2. **Большинство строк не имеют прямых ссылок** — они лежат инлайн в
   конфиг-структурах; код грузит базу структуры. Примеры:
   - `BLT+BUTTON+IO1..6+1\r\n` — таблица с 2-байтовым префиксом,
     база `0x060625F6` (сами команды с `0x060625F8`);
   - кластер MCU/BLE-сообщений `MCU+PWR+OFF+0000`, `BLT+OFF+ACK+0000`,
     `DUT+TST+BLE+NAM+GET` — база `0x06062668`;
   - кластер `DUT+TST+MAC+GET+FF*`, `EDIFIER MR5` — база `0x06062884`.
3. **Дальние call (-99.5…−100.5 млн)** реально встречаются в коде
   инициализации (напр. `sub_0600a278`) — цель вне флеш-окна; вопрос
   адресации ROM/банка остаётся открытым (риск №2 плана).

## 4. Якоря → подсистемы (функции для разбора в B4)

| подсистема | строки-якоря | функции (по ссылкам) | уверенность |
|---|---|---|---|
| Сканер кнопок/IO | `BLT+BUTTON+IO1..6` | `sub_06002224` (comp 'B'/'A', тайминги, структура состояния на r5) | высокая — это key-scan + отправка BLE-команд |
| MCU-протокол (UART) | `MCU+PWR+OFF+0000`, `BLT+OFF+ACK+0000` | отправитель: `sub_0600a278` (загрузка кластера `0x06062668` @`0600a5b6`); парсер — искать приёмный путь кластера | средняя |
| Сервисный DUT/TST | `DUT+TST+MAC+GET/SET`, `TST+DUT+BLE+NAM+GET`, `TST+LED+IO*` | `sub_0600ac08`, `sub_0600d698`, `sub_0602b98c`, `sub_06017c92` (кластер `0x06062884`) | средняя |
| BT-имена / GAP-конфиг | `EDIFIER MR5`, `EDIFIER BLE` | `sub_0600a6a2` (`EDIFIER BLE` +2), `sub_0600ac08` (кластер с `EDIFIER MR5`) | высокая для факта ссылок |
| jlstream-фреймворк | `jlstream_0..b` | `sub_06038554` (прямая ссылка `jlstream_0`), caller-цепочка `sub_06038892` → 6+ callers | высокая |
| EQ/аудио-эффекты | `MusicEq`, `Eq0Media`, `SET_HP_GAIN` | `sub_06013cf2`, `sub_06016d36` (MusicEq), `sub_06006390` (SET_HP_GAIN, 2 ссылки) | высокая |
| USB-стек | `usb_stack` | кластер `sub_0602c2c0…sub_0602d12c` (6 ссылок на пул имён задач) | высокая |
| Тоны | `tone_zh/power_off.*` и др. | таблицы указателей на имена тонов возле `0x0605FAxx`; загрузчик — `sub_06007d8c` и др. | средняя |

Полные цепочки «строка → инструкция → функция → вызывающие» — в
`disasm/string_xrefs.md` §1; компактный список всех 89 строк со ссылками —
§2; строки-инлайн в структурах — §3; кандидаты на именование — §4.

## 6. Восстановление стартов скрытых функций (A3-prep, 2026-11-18)

Инструмент: `tools/hidden_funcs.py` → `disasm/hidden_funcs.txt`.

Метод: для каждого из 248 «вне-декодных» mov32-сайтов — обратный скан
(шаг 2 Б) с линейным декодом pi32v2isa; кандидат C принят, если линейный
деком от C чисто доходит до сайта (сайт = начало инструкции) и продолжается
≥24 Б после него; берётся самый ранний такой C.

Результат: **246 стартов** (221 верифицировано обратным декодом, 27 —
fallback на сам сайт, после дедупликации). Из них ~17 с явным
прологом-пушем; крупнейшие кандидаты: `0601c54a` (~6.6 КБ), `06025170`
(~7.1 КБ, пролог), `0602dd34` (~11 КБ — вероятно, функция + таблицы,
границы уточнит Ghidra-анализ).

Импорт в Ghidra (2026-11-18, headless): скрипт
`ghidra_scripts/AddHiddenFuncs.java` (проект `ghidra_proj/MR5`,
программа `app_bin_full.bin`, память `ram` = 0x06000100…0x0608EFFB):
- 246 скрытых стартов → created=245, failed=1 (закладки «hidden-func-B2»);
- заодно **все 2 553 call-цели** рекурсивного дизасма
  (`disasm/known_starts.txt`) → created=2551, failed=2
  (закладки «func-B2-listing»);
- итог в программе: **2 812 функций**, все в отображённой памяти.

Ограничение: язык `pi32v2:LE:32:default` (частичная спека kagaimiq)
декодирует ~9 500 инструкций на весь образ — функции пока «контейнеры»
с закладками; после A1 (полная SLEIGH) листинг наполнится автоматически.
