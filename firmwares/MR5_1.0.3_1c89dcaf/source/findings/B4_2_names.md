# B4.2 — ручное именование функций (2026-11-18)

Инструменты: `tools/b42_collect.py` (агрегат «функция → вызовы/imm/строки»
из листинга + строк из app.bin → `disasm/b42_funcs.json`), `tools/b42_names.py`
(манифест `disasm/b42_manifest.json`), `ghidra_scripts/B42Apply.java`
(применение), `tools/b42_dossier.py` (досье функции), `tools/show_c.py`
(C-тело из `ghidra_export/mr5_decomp_all.c`), `tools/show_func.py` (asm).

## 1. Почему имён мало (32, а не 100–200)

Плановые 100–200 предполагали размножение имён через сигнатуры SDK (B3) —
B3 заблокирован (нет эталонов). Больше половины строковых «якорей» лежат
инлайн в общих таблицах (окно 512 Б ловит одни и те же данные из десятков
функций — фильтр шума отсёк 79 строк: имена узлов аудио-графа
`Band/Bass/Gain/DyEq`, `app_core/local_tws`, градиентная ASCII-таблица и
др.). Бинарный мусор (float/код-таблицы тоже читаются как printable)
отсеян эвристиками: маркеры `/`/`_`/`+`/`слово.`, дистанция imm→строка
≤ 128 Б, ≥4 различимых букв, без серий >3, без мусорных символов.

## 4. Наблюдения для дальнейшей работы

1. **0600ba7c — главный диспетчер команд**: единственный владелец кластера
   `DUT+TST+*SET`; вызывается косвенно (прямых callers нет — только
   self-call, вероятно хвостовая рекурсия/цикл диспетчера). Кандидат на
   разбор протокола MCU (B4.3?).
2. **dut_tst-кластер собран**: cmd_handler (0600ba7c) → get_resp
   (06013202) → get_send (06014348) → strtbl_get_a/b (060109f0/06010a06) +
   ранее именованные dut_tst_cluster{,_2,_3,_4}.
3. **Кластер ресурсов**: app_dir_head ×4 (06072282..06072e1c) — таблица
   каталогов flash (`app_dir_head`, `ota.bin`, `cfg_tool.bin`,
   `flash.bin`) — согласуется с C1 (ресурсный хвост).
4. Декомпилированный C (`mr5_decomp_all.c`) для этих функций малоинформативен
   (сделан до B1.3-заглушек; «Subroutine does not return» шум) — разбирать
   по asm/строкам; после B3-сигнатур C станет пригоднее.
