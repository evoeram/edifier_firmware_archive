## 1. Цели

1. **Полное понимание MR5**: карта функций, разбор ключевых подсистем
   (BT-стек JieLi jlstream, аудио-DSP, MCU-протокол, BLE-сервис Edifier).
2. **Воспроизводимый тулчейн**: любой желающий расшифровывает и дизассемблирует
   любую из 13 прошивок архива одной командой.
3. **Возможность модификации**: патч прошивки + корректная упаковка/решифровка
   (для OTA-экспериментов — на свой страх и риск).
4. **Документация семейства**: чем различаются 12 моделей (аудио-граф, EQ,
   калибровки), где лежат ресурсы.

Не-цели: обход безопасности устройств, пиратство, распространение
прошивок третьим лицам.

## 2. Что уже установлено (фактура)

### 2.1 Шифр (см. `source/ANALYSIS.md` §2)
- Весь файл поблочно скремблирован **SFC-шифром JieLi**:
  блоки 32 Б на смещениях ≡ 2 (mod 32); `seed = 0x2BC1 ^ ((bs−2)>>2)`;
  кейнстрим — LFSR `s' = (s<<1) ^ 0x1021`, выход = младший байт.
- Ключ **0x2BC1 общий для всех 12 моделей** (это, вероятно, «chipkey»
  Edifier-семейства, а не per-device ключ).
- Дешифратор: `source/decrypted/decrypt_all.py` (зависимость — только Python 3).

### 2.2 Контейнер (JLFS)
Записи по 32 Б от смещения 2:
`hcrc:u16 | data_crc:u16 | off:u32 | size:u32 | flags:u8 | rsvd:u8 | idx:u16 | name[16]`
(CRC16 poly 0x11021, init 0 — `jl_crc16`).

| запись | смысл |
|---|---|
| `app_area_head` | заголовок app-области; поле off = **точка входа 0x06000100** |
| `app.bin` | код+rodata, данные с файла 0x100 |
| `VM` / `PRCT` / `BTIF` | reserved-определения флеш-карты (2 МБ NOR) |

Инструмент: `source/tools/jlfs_parse.py`.

### 2.3 Память (MR5)
- NOR 2 МБ; XIP-окно кода **0x06000000**; app.bin @ флеш 0x100 → 0x06000100.
- RAM: стек `sp = 0x103840`; .data копируется из флеша в RAM (3884 + 44 080 Б);
  BSS очищается (0x105540…); затем `goto 0x06018310` (кандидат в main).
- Признаки второй области исполнения (дальние `call.xl` с целями вне
  флеш-окна — проверить: отдельный банк / RAM-оверлей / ROM).

### 2.4 Содержимое (по строкам app.bin)
- JieLi SDK нового поколения: `jlstream_0..b`, `pmu_task`, `usb_stack`,
  `a2dp_dec`, `tws_ota_msg`, `spec_adv0..3` и т.д.
- Edifier-слой: BT-имена `EDIFIER MR5`/`EDIFIER BLE`; MCU-протокол
  (`MCU+PWR+OFF+0000`, `BLT+OFF+ACK+0000`); сервис-команды
  (`DUT+TST+MAC+GET`, `TST+LED+IO1..3`, `BLT+BUTTON+IO1..6`);
  EQ-пресеты (`Desk_Acoustic`, `TrebShelf_LB4`); tone-файлы `tone_zh/*`;
  ресурсы `flash/res/*.bin`, `storage/nor_ui`.

### 2.5 Инструментальная база
- **Дизасм**: `jvitkauskas/pi32v2-isa` — аппаратно верифицированная таблица
  инструкций + objdump (Python). Обёртка: `source/tools/disasm_mr5.py`.
- **Ghidra 12.2** + SLEIGH `pi32v2:LE:32:default` собран и установлен
  (спека `kagaimiq/ghidra-jieli` — **частичная**, для декомпилятора мало).
- Эталоны: plaintext-образы AC695N SDK (`std_app.bin`, `jl_isd.bin`)
  в `Temp\opencode\jl_sdk_dl\`.

## 4. Ключевые риски и открытые вопросы

1. **SLEIGH-генерация из TOML** (A1) — самый объёмный шаг. Fallback:
   дизасм через `pi32v2isa` (уже работает) + собственный паттерн-поиск,
   декомпиляцию отложить.
2. **Дальние `call.xl`** — цели вне флеш-окна (пр.: `call -99532978`
   из crt0). Гипотезы: вызовы в ROM/загрузчик (0x1E0xxxx?), другой банк.
   Уточнить по документации AC79xx (см. `docs/` в pi32v2-isa).
3. **Образ неполный**: файл — только app-область (0xAA50C из 2 МБ флеша);
   ресурсы `flash/res/*` в дамп не входят. Нужен полный образ (обновление
   большего размера, сервисный дамп) — иначе C2 ограничен.
4. **Часть данных app.bin не покрыта дизасмом** (30.7 %): таблицы переходов
   (косвенные goto), строковые пулы, константы. Требует ручной разметки
   после A3.
5. **Ключ 0x2BC1** может быть не единственным (другие линейки Edifier/другие
   вендоры JieLi — свои chipkey). Дешифратор параметризован.

## 5. Как воспроизвести (шпаргалка)

```powershell
# 4. Ghidra: проект уже собран в Temp\opencode\ghidra_proj (MR5);
#    язык pi32v2:LE:32:default установлен в Ghidra\Processors\JieLi
```

`tools/state_rec.py` → `tools/segmap.py` → `tools/solve_kb2.py`
(описание — `ANALYSIS.md` §2.2).
